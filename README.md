# game_shy_ — ARROWFALL

방을 하나씩 돌파하며 능력을 쌓는 탑다운 로그라이트.
의존성 없는 캔버스 게임이라 빌드 도구도, 외부 라이브러리도, 에셋 파일도 없다.
`index.html` 을 브라우저로 열면 바로 실행된다.

![플레이 화면](docs/gameplay.png)

## 실행

```bash
open index.html     # macOS  (Windows: start / Linux: xdg-open)
npm start           # 또는 로컬 서버 — http://localhost:8080
```

## 조작

타이틀에서 두 가지 조작 방식 중 하나를 고른다.

| | 자동 발사 | 수동 조준 |
| --- | --- | --- |
| 발사 | **멈추면** 자동으로 가장 가까운 적을 쏜다 | 마우스로 조준하고 눌러서 쏜다 |
| 이동 중 | 쏘지 못한다 | 쏠 수 있다 |
| 보정 | 피해 **+15%** | 없음 |

멈춰야 쏘는 쪽이 더 위험하므로 그만큼 피해를 얹었다. "피할 것인가 쏠 것인가"의
긴장이 자동 발사 모드의 핵심이다.

| 동작 | 키 |
| --- | --- |
| 이동 | `WASD` · `←↑↓→` · 왼쪽 가상 스틱(터치) |
| 조준·발사 | 마우스 · `Space` · 오른쪽 가상 스틱(터치) |
| 능력 선택 | `1` `2` `3` · 카드 클릭 |
| 일시정지 | `P` · `Esc` |
| 음소거 | `M` |

모바일은 화면을 좌우로 나눠 가상 스틱 두 개가 생긴다.
왼쪽이 이동, 오른쪽이 조준이다. 자동 발사 모드에서는 왼쪽만 있으면 된다.

**키가 안 먹으면 화면을 한 번 클릭한다.** iframe(아티팩트 등)에 끼워 넣고 돌릴 때
프레임이 포커스를 갖고 있어야 키 이벤트가 도착한다. 캔버스에 `tabindex` 를 주고
누를 때마다 포커스를 가져오며, 포커스를 잃으면 게임을 멈추고 그 이유를 화면에
띄운다 — 그러지 않으면 적은 계속 오는데 조작만 죽어 고장난 것처럼 보인다.

## 규칙

- 방의 적을 전멸시키면 **능력 3개 중 1개**를 골라 강해지고 다음 방으로 간다.
- **5방마다 보스**가 나온다. 보스를 잡으면 최대 체력의 30% 를 회복한다.
- 체력은 방을 넘어가도 회복되지 않는다. 회복 수단은 능력뿐이다.
- 방이 진행될수록 적의 체력·피해와 수가 늘고, 등장하는 종류도 늘어난다.

원거리 적은 엄폐물 뒤에 숨지 않는다. 플레이어가 일정 시간 보이지 않으면
사거리를 버리고 보일 때까지 다가온다. 그러지 않으면 서로 아무것도 못 하는
교착이 되어 방이 끝나지 않는다.

## 구조

```
index.html          캔버스 한 장과 스크립트 로드
css/font.css        Pretendard 서브셋 (생성물 — tools/build-font.js 가 만든다)
css/style.css       캔버스를 화면에 맞추는 레이아웃만
js/util.js          수학 · 원-사각형 충돌 · 가중치 뽑기
js/audio.js         WebAudio 로 즉석 합성하는 효과음 (에셋 없음)
js/input.js         키보드 / 마우스 / 멀티터치 가상 스틱
js/particles.js     고정 크기 풀을 돌려 쓰는 파티클 + 데미지 숫자
js/content.js       상수 · 적 정의 · 능력 목록 · 방 배치  ← 튜닝은 여기서
js/sprites.js       스프라이트 매니페스트 + 로더  ← 아트 규격은 여기서
js/sprite-data.js   스프라이트 이미지 (생성물 — tools/build-sprites.js 가 만든다)
js/entities.js      플레이어 · 투사체 · 적 AI
js/game.js          상태 기계 · 방 진행 · 길찾기 · 렌더링
js/main.js          부팅 + 고정 스텝 루프
assets/             스프라이트 PNG 원본 ← 진짜 아트를 여기 덮어쓴다
test/               데이터 검증 + 브라우저 스모크/스트레스 테스트
tools/              빌드 스크립트 (단일 파일 묶기 · 서체 · 스프라이트)
```

ES 모듈 대신 전역 `AF` 네임스페이스를 쓴다. `file://` 로 열었을 때 CORS 에
막히지 않게 하기 위한 선택이다.

물리는 화면 주사율과 무관하게 항상 1/60초 고정 스텝으로 돈다.
120Hz 모니터에서 적이 두 배로 빨라지지 않는다.

### 서체

Pretendard 를 쓴다. 다만 CDN 링크가 아니라 **게임이 실제로 그리는 글자만 남긴
서브셋을 data URI 로 심었다**(`css/font.css`). 이유는 두 가지다.

- 저장소는 네트워크 없이 `file://` 로 열려야 한다. 외부 링크는 그 성질을 깬다.
- 아티팩트로 게시할 때 CSP 가 외부 스타일시트를 `fonts.googleapis.com` 으로만
  허용하는데 Pretendard 는 거기 없다. 링크로는 **오류 없이 조용히** 실패한다.

두 굵기 원본 1521KB → 서브셋 34KB (289자, 한글 음절 156자).
서체 스택은 `AF.FAMILY` 한 곳에만 있고 캔버스는 `AF.font(px, weight)` 로 쓴다.

캔버스는 서체가 준비되기 전에 그리면 조용히 대체 서체로 떨어지므로,
`document.fonts` 가 준비될 때까지 기다렸다가 루프를 시작한다(1.2초 뒤에는
기다리지 않고 시작 — 대체 서체로 도는 게 검은 화면보다 낫다).

**화면에 새 문구를 추가했으면 서브셋을 다시 만들어야 한다.**
없는 글자는 오류 없이 대체 서체로 떨어져 눈치채기 어렵다.

```bash
node tools/build-font.js     # js/ 와 index.html 에서 글자를 다시 수집해 재생성
```

필요한 것: `pip install fonttools brotli`

### 길찾기

적은 12x12 격자 위에서 **너비 우선 탐색으로 만든 거리장**을 따라 움직인다.
플레이어가 보이면 그냥 직진하고(격자를 따라가면 움직임이 각져 보인다),
보이지 않을 때만 거리장을 따른다.

앞을 조금 짚어 보고 좌우로 트는 국소 조향으로 먼저 만들었다가 버렸다.
폭이 넓은 벽 앞에서 적이 벽을 밀며 멈춰 버려 방이 끝나지 않았다.
격자가 144칸뿐이라 매번 새로 구해도 부담이 없다.

## 스프라이트 (아트 교체하기)

**스프라이트는 선택 사항이다.** 파일이 있으면 그걸 그리고, 없으면 예전처럼
캔버스 도형으로 떨어진다. 그래서 그림을 한 장씩 갈아 끼워도 중간에 화면이 깨지지
않는다 — 바꾼 것만 바뀌고 나머지는 그대로 돈다.

지금 `assets/` 에 든 건 **자리 채우기**다. 기존 도형을 그대로 PNG 로 옮긴 것이라
화면이 달라 보이지 않는다. 목적은 그림이 아니라 크기·중심·로딩·폴백을 미리
검증해 두는 것이다.

### 진짜 아트 넣기

1. `assets/<키>.png` 를 **같은 이름으로 덮어쓴다** (투명 배경 PNG)
2. `node tools/build-sprites.js`
3. 끝. 매니페스트나 렌더러는 건드릴 필요가 없다

| 키 | 크기(2배 해상도) | 비고 |
| --- | --- | --- |
| `player` | 112x112 | |
| `enemy-chaser` | 112x112 | |
| `enemy-shooter` | 112x112 | |
| `enemy-orbiter` | 120x120 | |
| `enemy-charger` | 136x136 | |
| `enemy-splitter` | 160x160 | |
| `enemy-shard` | 80x80 | |
| `enemy-boss` | 280x280 | |
| `arrow` | 48x48 | 오른쪽을 보게 그린다 |
| `bolt` | 48x48 | 적 탄 |
| `floor` | 112x112 | 이어 붙여도 이음매가 안 보이게 |
| `wall` | 112x112 | 엄폐물 한 칸 |

**스프라이트 중심 = 캐릭터 중심**으로 맞춘다. 히트박스보다 그림이 커도 된다 —
모자·활·날개가 삐져나오는 건 정상이고, 그러라고 히트박스 지름의 2.15배로 그린다.
히트박스 자체는 `js/content.js` 의 `r` 이며 난이도가 거기 맞춰져 있으니 건드리지
않는 편이 좋다.

### 방향 처리

`js/sprites.js` 의 `AF.SPRITES` 에서 스프라이트마다 정한다.

| `face` | 동작 | 쓰는 곳 |
| --- | --- | --- |
| `rotate` | 진행/조준 방향으로 회전 | 삼각형·화살처럼 방향이 뚜렷한 것 |
| `flip` | 좌우 반전만 | 옆을 보는 캐릭터 그림 |
| `none` | 그대로 | 위에서 본 것, 타일 |

옆모습 캐릭터를 회전시키면 거꾸로 서니, 사람 그림은 `flip` 을 쓴다.

### 자리 채우기 다시 만들기

```bash
python3 tools/make-placeholders.py    # pip install Pillow 필요
node tools/build-sprites.js
```

색은 `js/content.js` 에서 읽어오므로 색을 바꾸면 자리 채우기도 따라온다.

## 방 배치 추가하기

`js/content.js` 의 `ROOMS` 배열에 항목을 더한다.
**한 줄이 정확히 12글자, 12줄**이어야 하고 `#` 이 엄폐물, `.` 이 빈 바닥이다.
아래 두 줄은 플레이어가 등장하는 자리라 비워 둔다.

```js
[ '............',
  '..##....##..',
  '............',
  /* ... 12줄 ... */
  '............' ]
```

고쳤으면 검증부터 돌린다. 줄 길이가 어긋나거나 모르는 글자가 있으면 잡아 준다.

```bash
npm test
```

## 테스트

```bash
npm test              # 데이터 검증 — 의존성 없음
npm i                 # 브라우저 테스트용 playwright 설치
npm run test:browser  # 정상 경로 27개 항목
npm run test:stress   # 경계 / 장시간 / 극단 빌드 23개 항목
```

`test/content.test.js` 는 손으로 적는 데이터를 본다 — 방 배치 문법, 엄폐물 비율,
능력 id 중복과 상한, 모든 능력을 상한까지 쌓았을 때 스탯이 망가지지 않는지,
보스 주기와 난이도 곡선. 스프라이트도 함께 본다 — 적 종류마다 키가 선언돼 있는지
(없으면 그 적만 조용히 도형으로 그려진다), `assets/` 에 매니페스트가 모르는 파일이
없는지, 생성물이 최신인지.

`test/smoke.js` 는 정상 경로를 본다 — 조작 모드 전환, **자동 발사가 멈췄을 때만
나가는지**, 수동 조준이 이동 중에도 나가는지, 방 클리어 → 능력 선택 → 다음 방,
보스 등장, 사망, 최고 점수 저장.

`test/stress.js` 는 경계를 노린다 — 적 7종 동시 투입, 능력 16종 최대 중첩,
능력 풀 고갈, 20방 연속 진행, 막힌 방에서의 등장 좌표, 도탄 최대에서 화살이
전장을 벗어나지 않는지, 무작위 상태 전이, 뷰포트별 포인터 좌표 정합.
그리고 **실제로 있었던 결함의 회귀 테스트** — 벽 뒤에서 출발한 적이 반드시
플레이어에게 도달하는지, 시야가 막혀도 방이 끝나는지.

시스템에 설치된 다른 크로미움을 쓰려면 `PW_CHROME=/path/to/chrome` 으로 지정한다.

## 파일 한 장으로 묶기

```bash
node tools/build-artifact.js               # dist/arrowfall.html (감싸기용 조각)
node tools/build-artifact.js --standalone  # dist/arrowfall-standalone.html (그냥 열면 됨)
```

서체까지 인라인되므로 결과물은 네트워크 없이 혼자 돈다.

`index.html` 이 참조하는 CSS/JS 를 적힌 순서대로 인라인한다.
스크립트 태그 순서가 곧 의존 순서이므로, 파일을 추가하면 `index.html` 에만
반영하면 빌드가 따라온다.
